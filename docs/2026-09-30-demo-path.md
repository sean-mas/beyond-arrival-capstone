# Demo path, 30.09.2026

Five minutes, live on https://beyond-arrival-deploy.onrender.com. Every step
below was run on localhost on 30.09 and did what it says; the answers are
written by a model, so the wording changes from run to run.

## Before you start

| When | What |
|---|---|
| 2 minutes before | Open the site once. Render's free server sleeps after 15 idle minutes and takes about a minute to wake. |
| 2 minutes before | Send one message and enter the access code, so the code prompt doesn't interrupt the demo. The code stays for the browser tab. |
| Before | Use one tab for the whole demo. Have a second, private window ready for step 1. |

## The path

| # | Show | Click or type | Say |
|---|---|---|---|
| 1 | **The welcome** (private window, `/chat`) | Nothing, or "Make it yours" and one onboarding step | "A family's companion after the move, from their relocation provider. Five questions and it becomes theirs; everything stays on their device." |
| 2 | **A family, ready-made** | Open `/chat?demo=1` | "Sean, Ana and Leo, moving from Lisbon to Koblenz in 12 days. The link skips the five questions." |
| 3 | **The journey** | Tap **Prepare the move** | "Four stops from home to settled. Each stop holds the family's to-dos, dated from the moving day. The first stop is already done." |
| 4 | **An answer** | Chat tab, tap **How do I register our address?** | "Three steps show what it is doing. The answer comes only from the provider's own material, and it ends with one concrete next step." |
| 5 | **Into the checklist** | Tap **Add to checklist** under the answer | "What they read becomes something they do." |
| 6 | **What happened underneath** | Switch to **Inspector** | "Personal data is removed first. The safety checks run in code. Then the cards it found, the route the model chose, and a check that the answer is backed by the cards." |
| 7 | **Personal data** | Type: *My phone is 0151 2345 6789 and we moved to Koblenz last week. How do I register our address?* | "The number is replaced before any model reads it; the inspector shows the message as the model saw it." |
| 8 | **A person, not a bot** | Tap **I would like to talk to a person** | "The handover is decided in code, not by the model: no model wrote this reply. The family is told who sees the conversation, and 112 is always there." |
| 9 | **Children have no chat** | Tap the face top right, switch to **Leo** | "A child gets their own to-dos and no chat. A child alone with a model is a safety question, not a feature." |

## If something goes wrong

| What | Do |
|---|---|
| The first message takes a minute | The server was asleep. Say so: "free hosting, it wakes up", and carry on. |
| An answer is slow (15 to 20 s is normal) | Talk over the three progress steps; that is what they are for. |
| "Something went wrong" on a turn | Tap the starter again. If it repeats, switch to the Inspector view of an earlier turn and show that. |
| The access code prompt appears | Enter the code; it is in the message the link was sent with. |

## Honest limits, if asked

- The live crisis check runs on a hosted model with recall 0.622, against 0.865 for the local model the evaluations use. That gap is measured and in the deck.
- The family lives on one device (browser storage). Accounts and a second login for the partner are the next step, after a data-protection read on children's data.
- The provider name is a placeholder.
